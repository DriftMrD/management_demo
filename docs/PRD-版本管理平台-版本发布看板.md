# PRD：版本管理平台 · 版本发布看板

| 字段 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 状态 | 待设计评审 |
| 关联系统 | 项目管理 · 版本管理平台 |
| 关联模块 | 需求池看板、研测专区看板、班车看板、用户反馈 |
| 核心目标 | 把「可发布版本」从研测产出沉淀为对外发布资产，支持计划发布 → 灰度放量 → 全量的状态与时间线追踪 |
| 本文用途 | 给视觉 / 交互设计对齐信息架构、页面清单、字段与状态视觉，产出列表页 + 详情页样式 |

---

## 1. 背景与问题

版本管理平台当前已有：

| 模块 | 现状 | 解决的问题 |
|---|---|---|
| 用户反馈 | 已上线 Demo | 发布后的用户声音 |
| 班车看板 | 已上线 Demo | 月度班车各阶段排期（规矩 / 灰度 / 全量 / 回顾等） |

仍缺一块：**单个版本的发布与放量过程**。

产品 / 运营需要回答：

1. 哪些版本已经从研测出来、准备对外发？  
2. 计划发哪个渠道、Release Note 是什么？  
3. 当前灰度到百分之几、何时开始放量？  
4. 放量是逐步的，历史怎么走的？（不是只看当前一个数字）

因此新增 **版本发布看板**：以「版本」为行，承接研测产出的 APK / 版本号，由产品与运营补齐发布计划与放量信息；点击进入详情看 **灰度百分比 × 放量时间线**。

> 说明：放量是逐步的。列表看当前态；详情看时间线。

## 2. 产品定位与信息架构

### 2.1 在版本管理平台中的位置

```
项目管理
└── 版本管理平台（version.html）
    ├── 用户反馈          ← 已有
    ├── 班车看板          ← 已有（月度节奏）
    └── 版本发布看板      ← 本期新增（单版本发布 / 放量）
```

平台首页（`version.html`）新增第三张模块卡：

| 模块名 | 说明文案（建议） | 角标（建议） |
|---|---|---|
| 版本发布看板 | 沉淀可发布版本，跟踪计划发布、灰度放量与全量进度 | `N 个计划中` / `M 个放量中` |

面包屑：

`项目管理 / 版本管理平台 / 版本发布看板`  
`项目管理 / 版本管理平台 / 版本发布看板 / {版本号}`

### 2.2 与上下游关系

```
需求池看板 ──► 所属产品
研测专区看板 ──► 释放时间 / APK 链接 / 版本号（写入或同步）
        │
        ▼
  版本发布看板（本模块）
        │  产品：发布状态、release note、渠道；可关联班车月份
        │  运营：放量时间、灰度百分比（及变更历史）
        │
        ├──► 班车看板（选择已有「班车月份」关联）
        └──► 用户反馈（同版本号可跳转查看反馈，本期可不做深链）
```

| 对象 | 定义 | 示例 |
|---|---|---|
| Product | 产品线 | Visha / Notes / Themes… |
| ReleaseVersion | 一次可对外发布的包版本 | `17.0.0.001` |
| ReleaseStatus | 发布状态 | 不涉及 / 计划中 / 已发布 |
| Channel | 上架渠道 | GP / PS / PA |
| ShuttleMonth | 关联的班车（来自班车看板） | `7月份班车` |
| GrayScalePoint | 某次灰度记录（时间 + 百分比） | `2026-07-01 · 10%` |

## 3. 目标用户与主路径

| 角色 | 诉求 |
|---|---|
| 产品经理 | 把研测产出的包标成「计划中」，填 Release Note / 渠道，关联班车 |
| 运营 | 录入放量时间与灰度百分比，推进到全量 |
| 产品 / 研发负责人 | 列表扫一眼各版本发布进度；进详情看放量节奏 |

主路径：

1. 研测侧填写 APK 链接与版本号 → 版本自动进入看板（释放时间默认取填写日）  
2. 产品将发布状态改为「计划中」→ 必填 release note、渠道；灰度默认 0%；可选关联班车月份  
3. 运营填写放量时间，并逐步上调灰度百分比  
4. 灰度 > 0% 时，状态自动变为「已发布」  
5. 点击版本进入详情，查看灰度百分比–放量时间线

## 6. 发布状态机与校验（影响组件状态）

```
                    产品改为「计划中」
        ┌──────────────────────────────────┐
        │  · 必填 release note、渠道        │
        │  · 灰度自动填 0%                  │
        │  · 可选关联班车月份               │
        ▼                                  │
  [不涉及] ──────────────────────► [计划中] ──►（运营改灰度）
  默认                                      │
                                            │  灰度百分比 > 0%
                                            │  系统自动改状态
                                            ▼
                                       [已发布]
```

| 规则 | 行为 |
|---|---|
| 默认 | 新版本发布状态 = **不涉及** |
| 需要对外发 | 人工改为 **计划中** |
| 计划中 | release note、渠道变为必填；未填不可保存 |
| 进入计划中 | 灰度百分比自动 = **0%** |
| 灰度 > 0% | 发布状态自动变为 **已发布**（无需再选手动「已发布」，或「已发布」仅展示、不可逆向手改到计划中——实现可再定，设计需区分「系统写入」与「人工选择」） |
| 100% 灰度 | 视为全量；视觉需与未全量明显区分 |

**三个状态的视觉建议（设计定稿）：**

| 状态 | 语义色建议 | 列表呈现 |
|---|---|---|
| 不涉及 | 中性灰 | Tag |
| 计划中 | 信息蓝 / 提醒色 | Tag |
| 已发布 | 成功绿 | Tag；若灰度未到 100% 可副文案「放量中」 |

**灰度档位色阶（设计定稿，示意）：**

| 区间 | 含义 | 视觉 |
|---|---|---|
| 0% | 未开始放量 | 灰 |
| 1%–49% | 小流量 | 浅强调色 |
| 50%–99% | 放量中 | 中强调色 |
| 100% | 全量 | 强成功色 / 实心「全量」标签 |

## 7. 页面需求详述

### 7.1 列表页 · 版本发布看板

**页面目的**：一眼扫清各产品版本的发布进度。

#### 布局示意

```
┌──────────────────────────────────────────────────────────────────┐
│ 面包屑：项目管理 / 版本管理平台 / 版本发布看板                     │
│ 版本发布看板                          [产品▾] [状态▾] [搜索版本] │
│ 副文案：跟踪计划发布、灰度放量与全量进度                           │
├──────────────────────────────────────────────────────────────────┤
│ 表头：产品 | 版本号 | 发布状态 | 灰度% | 放量时间 | 释放时间 | APK | 操作 │
│ 行…                                                              │
│ 行…  ← 整行可点进详情；版本号强调可点                             │
├──────────────────────────────────────────────────────────────────┤
│ 共 N 条                                      < 分页 >            │
└──────────────────────────────────────────────────────────────────┘
```

#### 交互

| 操作 | 行为 |
|---|---|
| 筛选产品 / 状态 | 顶栏 filter，样式对齐用户反馈 / 班车 |
| 点击版本号或行 | 进入版本详情 |
| 编辑发布信息 | 「编辑」打开抽屉或弹窗：状态、note、渠道、关联班车 |
| 运营改灰度 / 放量时间 | 可在列表快捷改，或仅在详情改（设计二选一，推荐详情为主、列表只读展示） |
| APK | 外链图标，阻止冒泡，不触发进详情 |

#### 空态 / 加载

- 无数据：说明「研测填写 APK 与版本号后将自动出现」  
- 筛选无结果：常规空态 + 清空筛选  

风格对齐：用户反馈列表（`feedback.html`）的表格卡 + 分页条；不要做成重仪表盘。

---

### 7.2 详情页 · 版本放量时间线（设计重点）

**页面目的**：讲清「这个版本怎么一步步放出去的」。

#### 布局示意

```
┌──────────────────────────────────────────────────────────────────┐
│ 面包屑 … / 版本发布看板 / 17.0.0.001                               │
│                                                                  │
│  17.0.0.001          [已发布]  [灰度 35%]  [渠道 GP]              │
│  产品 Visha · 释放 2026-06-01 · 放量自 2026-07-01                 │
│  [打开 APK]  [关联班车：7月份班车 →]                              │
├──────────────────────────────────────────────────────────────────┤
│  Release Note                                                    │
│  （多行正文，支持较长文案）                                        │
├──────────────────────────────────────────────────────────────────┤
│  灰度百分比 – 放量时间线                                          │
│                                                                  │
│  0%─────10%─────35%──────────70%──────────────100%               │
│  │       │       │            │                 │                 │
│ 6/01    7/01    7/08         7/15              7/22              │
│ 计划中   开始放量  …            …                全量              │
│                                                                  │
│  （或纵向 Timeline：左日期，右百分比节点 + 简短备注）               │
└──────────────────────────────────────────────────────────────────┘
```

#### 时间线要求

1. **每个灰度变更是一个节点**：日期 + 百分比（可选备注：谁改的 / 说明）  
2. **横轴或纵轴均可**，优先可读、可扩展多节点（逐步放量）  
3. **当前百分比**在页头与时间线终点同步高亮  
4. **100% 节点**有「全量」语义，与中间灰度节点样式区分  
5. 尚无放量记录时：仅显示「计划中 · 0%」占位节点 + 引导运营录入  

#### 详情页还需展示

- 所属产品、释放时间、APK、版本号、发布状态  
- 放量时间、当前灰度、release note、渠道、关联班车  

#### 编辑入口

- 「更新灰度」：录入新百分比（及可选生效日期，默认今天）→ 追加时间线节点；若 >0% 触发状态变已发布  
- 「编辑发布信息」：note / 渠道 / 班车 / 计划中↔不涉及（受状态机约束）

---

### 7.3 编辑表单（抽屉或弹窗）

复用现有 `field-label` / `field-input` / 弹窗结构（参考班车新增弹窗、需求池新建）。

| 区块 | 字段 | 备注 |
|---|---|---|
| 只读 | 产品、版本号、释放时间、APK | 来自研测，本模块不改 |
| 产品可编辑 | 发布状态、release note、渠道、关联班车 | 计划中时 note+渠道必填标 `*` |
| 运营可编辑 | 放量时间、灰度百分比 | 日历 + 数字（0–100） |

校验失败：字段下红字或 toast，与现有系统一致。

## 11. 验收标准（设计评审用）

- [ ] 列表能区分不涉及 / 计划中 / 已发布，且放量中（已发布但未 100%）可感知  
- [ ] 灰度 0 / 中段 / 100% 全量有明确色阶，100% 一眼是全量  
- [ ] 详情时间线能讲清「逐步放量」，不是只显示当前一个百分比  
- [ ] 计划中编辑态能看出 note、渠道必填  
- [ ] 与版本管理平台现有两张模块卡、反馈列表视觉同源，不另起风格  
- [ ] 桌面优先可读；关键操作在一屏内可达

## 12. 开放问题（评审时拍板）

1. 列表是否展示当前灰度%（建议展示微型进度或色点）？  
2. 灰度更新只在详情，还是列表行内也可改？  
3. 「已发布」是否允许人工从下拉直接选，还是仅由灰度 >0% 自动写入？  
4. 关联班车在列表是否单独一列，还是仅详情展示？  
5. 多渠道同版本（同一版本号发 GP+PS）是一行多渠道，还是拆多行？本期字段表为单渠道，建议先单行单渠道。
